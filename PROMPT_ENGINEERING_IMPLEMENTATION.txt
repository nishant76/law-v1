### File: base_prompt.py

Content (350 lines):

1. **ModelType Enum**
   - GPT4O = "gpt-4o" (expensive, for drafts)
   - GPT4O_MINI = "gpt-4o-mini" (cheap, for extraction/synthesis)

2. **PromptTemplate Base Class**
   
   Constructor parameters:
   - system_prompt: str (instructions for model)
   - user_prompt_template: str (message with {placeholders})
   - model: ModelType (which model to use)
   - version: str (YYYY-MM-DD format, required)
   - temperature: float (0.0=deterministic, 1.0=creative)
   - max_tokens: Optional[int] (response size limit)
   - top_p: float (nucleus sampling, default 1.0)
   - description: Optional[str] (what this prompt does)
   
   Methods:
   - format_user_prompt(**kwargs) → str
     * Formats template with placeholder values
     * Validates all required placeholders provided
     * Raises KeyError if placeholder missing
   
   - get_config() → Dict[str, Any]
     * Returns full prompt configuration as dict
     * Useful for logging and debugging
   
   - _validate_version(version: str)
     * Ensures version format is YYYY-MM-DD
     * Raises ValueError if invalid format
   
   - _validate_temperature(temperature: float)
     * Ensures temperature in range [0, 1]
     * Raises ValueError if out of range
   
   - _get_placeholders() → list
     * Extracts all {placeholder} names from template
     * Used for validation
   
   Properties:
   - system_prompt
   - user_prompt_template
   - model
   - version
   - temperature
   - max_tokens
   - top_p
   - description

2. **Prompt Management Rules**
   
   Adding a new prompt:
   - Create backend/services/prompts/feature_name.py
   - Import PromptTemplate, create instance
   - Export in backend/services/prompts/__init__.py
   - Update REGISTRY.md
   - Create 10 test cases
   - Make PR with title [PROMPT] Feature: description
   - Get code review approval
   - Run regression tests (must pass 100%)
   
   Modifying an existing prompt:
   - Update prompt file
   - Change version to today's date
   - Update REGISTRY.md
   - Run all regression tests
   - Make PR explaining change
   - Get approval before merge

3. **Using Prompts in Services (Pattern)**
   
   CORRECT:
   ```python
   from backend.services.prompts.base_prompt import extract_document_fields_prompt
   
   # Always sanitise first!
   user_input = sanitise_user_input(raw_input)
   
   # Format the template
   formatted = extract_document_fields_prompt.format_user_prompt(
       document_content=user_input
   )
   
   # Call LLM
   response = await llm_service.call(
       system_prompt=extract_document_fields_prompt.system_prompt,
       user_prompt=formatted,
       model=extract_document_fields_prompt.model,
       temperature=extract_document_fields_prompt.temperature
   )
   ```
   
   WRONG (Never do this):
   ```python
   # Don't inline prompts
   # Don't pass unsanitised input directly
   # Don't use f-strings (injection vector!)
   ```

5. **Prompt Versioning Rules**
   
   - Format: YYYY-MM-DD (date format)
   - Never reuse version numbers
   - Version change = public record (in git)
   - Cannot change after RC tag cut
   
   Example version history:
   - 2024-04-08: Initial prompt
   - 2024-04-10: Improved extraction logic
   - 2024-04-15: Added PII guardrails
   (Can never go back to earlier versions)

6. **Model Selection Reference Table**
   
   When to use which model:
   
   gpt-4o-mini (cheap, fast):
   - Document extraction
   - Case synopsis generation
   - Field confidence scoring
   - RAG synthesis (retrieval + synthesis)
   - Smart reply generation
   - Citation verification
   
   gpt-4o (expensive, highest quality):
   - Filing drafts (expensive but must be perfect)
   - Complex legal reasoning (strategy, risk analysis)
   - When accuracy > speed
   
   Pricing:
   - gpt-4o-mini: ₹0.15/1M input tokens, ₹0.60/1M output
   - gpt-4o: ₹3/1M input tokens, ₹6/1M output

## Benefits of This Structure

1. **Version Control**
   - All prompts tracked in git
   - History of changes for every prompt
   - Can review what changed and why in PRs

2. **Consistency**
   - All prompts follow same structure
   - PromptTemplate ensures validation
   - Registry documents everything

3. **Safety**
   - PromptTemplate enforces template.format() pattern
   - Prevents inline f-strings (injection vectors)
   - Version pinning prevents accidental updates

4. **Testability**
   - 10 test cases per prompt required
   - Regression tests before every deploy
   - Catch breaking changes early

5. **Maintainability**
   - REGISTRY.md serves as single source of truth
   - Easy to find which prompt does what
   - Clear naming and documentation

6. **Scalability**
   - Add new prompts without touching service code
   - Same pattern for all features
   - Minimal changes to add new LLM features

## Usage Examples

### Example 1: Use Extract Document Fields

```python
from backend.services.prompts.base_prompt import extract_document_fields_prompt

async def extract_fields_from_document(raw_document: str, document_id: str):
    """Extract structured fields from document"""
    
    # IMPORTANT: Always sanitise user input first
    document_text = sanitise_user_input(raw_document)
    
    # Format prompt with document content
    user_prompt = extract_document_fields_prompt.format_user_prompt(
        document_content=document_text
    )
    
    # Call LLM through LLMService (never call directly)
    response = await llm_service.call(
        system_prompt=extract_document_fields_prompt.system_prompt,
        user_prompt=user_prompt,
        model=extract_document_fields_prompt.model.value,
        temperature=extract_document_fields_prompt.temperature,
        max_tokens=extract_document_fields_prompt.max_tokens
    )
    
    # Parse and return
    return json.loads(response)
```
